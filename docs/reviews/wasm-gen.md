## 2. Correctness & robustness

- **CONFIRMED:** For inputs already in the `u32` domain, `writeU32` implements conventional unsigned LEB128 termination, and `writeI32` implements signed termination based on the sign bit; section and function-body sizes are computed from the encoded byte counts rather than source-level element counts (`src/generator/wasm-builder.ts:477`, `src/generator/wasm-builder.ts:488`, `src/generator/wasm-builder.ts:402`, `src/generator/wasm-builder.ts:510`).
- **CONFIRMED:** Numeric inputs are not validated before coercion: `writeU8` masks to one byte, `writeU32` applies `>>> 0`, and `writeI32` applies `| 0`, so negative, fractional, non-finite, or out-of-range builder inputs can silently become different encoded values (`src/generator/wasm-builder.ts:473`, `src/generator/wasm-builder.ts:477`, `src/generator/wasm-builder.ts:488`).
- **CONFIRMED:** Standard sections emitted by `toBytes` are in increasing section-ID order, custom sections are placed before them as permitted by the format, and `writeSection` prefixes each payload with its encoded byte length (`src/generator/wasm-builder.ts:278`, `src/generator/wasm-builder.ts:283`, `src/generator/wasm-builder.ts:510`).
- **CONFIRMED:** Function indices account for preceding function imports, and later function imports are rejected once a local function exists, preventing already-returned local function indices from shifting (`src/generator/wasm-builder.ts:160`, `src/generator/wasm-builder.ts:193`, `src/generator/wasm-builder.ts:294`).
- **CONFIRMED:** Memory indices do not receive equivalent handling: `addMemory` counts only local memories, while memory imports are accepted even after local memories, so the returned local-memory index can disagree with the emitted combined index space (`src/generator/wasm-builder.ts:163`, `src/generator/wasm-builder.ts:170`, `src/generator/wasm-builder.ts:206`, `src/generator/wasm-builder.ts:283`, `src/generator/wasm-builder.ts:286`).
- **CONFIRMED:** Type indices, export indices/kinds/names, data-segment memory indices, and memory/table limits are accepted without range, existence, uniqueness, or `max >= min` checks; consequently the API can serialize modules rejected during validation (`src/generator/wasm-builder.ts:141`, `src/generator/wasm-builder.ts:193`, `src/generator/wasm-builder.ts:202`, `src/generator/wasm-builder.ts:206`, `src/generator/wasm-builder.ts:213`, `src/generator/wasm-builder.ts:368`).
- **CONFIRMED:** `Instruction` has no opcode-specific type shape, and the encoder validates only that listed load/store operations have two immediates; missing or extra immediates for constants, calls, `call_indirect`, memory size/growth, locals/globals, or no-immediate operations pass through to the byte stream (`src/generator/wasm-builder.ts:36`, `src/generator/wasm-builder.ts:408`, `src/generator/wasm-builder.ts:415`, `src/generator/wasm-builder.ts:420`, `src/generator/wasm-builder.ts:428`).
- **CONFIRMED:** Function bodies are emitted exactly as supplied and the builder does not append or verify a terminal `end`; an empty instruction array also yields an undefined opcode that is masked by `writeU8` if such an instruction is present (`src/generator/wasm-builder.ts:399`, `src/generator/wasm-builder.ts:409`, `src/generator/wasm-builder.ts:473`).
- **CONFIRMED:** Code/body, section, string, and data-byte length prefixes use the eventual encoded byte lengths, while data offsets use signed LEB128 and data bytes are copied on insertion (`src/generator/wasm-builder.ts:213`, `src/generator/wasm-builder.ts:402`, `src/generator/wasm-builder.ts:444`, `src/generator/wasm-builder.ts:447`, `src/generator/wasm-builder.ts:500`, `src/generator/wasm-builder.ts:510`).
- **LIKELY:** Mutable caller-owned arrays and objects can change output after insertion because types, function bodies/locals, import descriptors, and custom-section byte arrays are retained by reference; only data-segment bytes are defensively copied (`src/generator/wasm-builder.ts:141`, `src/generator/wasm-builder.ts:170`, `src/generator/wasm-builder.ts:193`, `src/generator/wasm-builder.ts:213`, `src/generator/wasm-builder.ts:221`).
- **LIKELY:** Metadata call-site offsets remain correct for the current template because the zero-local vector and `local.get 0` occupy three bytes before the first call and the target index is zero, making each generated call two bytes; the arithmetic is nevertheless coupled to those exact instruction encodings rather than derived from the encoder (`src/generator/js-wasm-glue.ts:234`, `src/generator/js-wasm-glue.ts:242`, `src/generator/js-wasm-glue.ts:250`, `src/generator/wasm-builder.ts:394`, `src/generator/wasm-builder.ts:428`).
- **SPECULATIVE:** The component has two differently shaped `metadata.code.call_targets` producers, one writing an empty target payload and the other a length-prefixed target/count pair; without a shared schema or validation, future format changes could update one path but not the other (`src/generator/wasm-builder.ts:246`, `src/generator/wasm-builder.ts:253`, `src/generator/js-wasm-glue.ts:330`, `src/generator/js-wasm-glue.ts:341`).

## 3. Coverage gaps

### Present or partially exercised

- The type enum covers `i32`, `i64`, `f32`, `f64`, `v128`, `funcref`, and `externref`, and function signatures permit multiple parameters and results; all three glue templates actually generate only `i32` signatures and operations (`src/generator/wasm-builder.ts:12`, `src/generator/wasm-builder.ts:38`, `src/generator/js-wasm-glue.ts:57`, `src/generator/js-wasm-glue.ts:157`, `src/generator/js-wasm-glue.ts:232`).
- The instruction table covers direct/indirect calls, local/global access, a small `i32` arithmetic set, `i32` loads/stores, memory size/growth, return, drop, no-op, and end; generated bodies use direct calls, local reads, `i32` add/subtract/multiply, no-op, and end (`src/generator/wasm-builder.ts:92`, `src/generator/js-wasm-glue.ts:61`, `src/generator/js-wasm-glue.ts:161`, `src/generator/js-wasm-glue.ts:234`, `src/generator/js-wasm-glue.ts:242`).
- Memory support includes local and imported descriptors, min/max limits, active data segments for memory zero or an explicit index, and `i32` memory opcodes; the glue templates only declare one bounded-random minimum memory and perform no memory access, growth, data initialization, import, or export (`src/generator/wasm-builder.ts:49`, `src/generator/wasm-builder.ts:170`, `src/generator/wasm-builder.ts:206`, `src/generator/wasm-builder.ts:213`, `src/generator/wasm-builder.ts:106`, `src/generator/wasm-builder.ts:114`, `src/generator/js-wasm-glue.ts:267`).
- Globals are represented as an import descriptor and export kind, with get/set opcodes, but there is no local-global collection or global section and no glue template uses a global (`src/generator/wasm-builder.ts:26`, `src/generator/wasm-builder.ts:33`, `src/generator/wasm-builder.ts:60`, `src/generator/wasm-builder.ts:96`, `src/generator/wasm-builder.ts:132`, `src/generator/wasm-builder.ts:272`).
- Imports and exports support all four core external kinds at the enum/writer level, while generated glue uses one function import and function exports only (`src/generator/wasm-builder.ts:22`, `src/generator/wasm-builder.ts:29`, `src/generator/wasm-builder.ts:319`, `src/generator/wasm-builder.ts:374`, `src/generator/js-wasm-glue.ts:158`, `src/generator/js-wasm-glue.ts:164`, `src/generator/js-wasm-glue.ts:68`, `src/generator/js-wasm-glue.ts:248`).
- Custom-section coverage includes a generic writer, three builder metadata helpers, and glue-local call-target and compilation-priority encoders; the metadata template emits instruction-frequency, call-target, and compilation-priority sections (`src/generator/wasm-builder.ts:221`, `src/generator/wasm-builder.ts:228`, `src/generator/wasm-builder.ts:246`, `src/generator/wasm-builder.ts:263`, `src/generator/js-wasm-glue.ts:253`, `src/generator/js-wasm-glue.ts:256`, `src/generator/js-wasm-glue.ts:262`).
- Cross-boundary paths include repeated JS-to-Wasm exported calls, a Wasm-to-JS imported call whose JS implementation throws, and a JS-to-Wasm call through a metadata-bearing module (`src/generator/js-wasm-glue.ts:88`, `src/generator/js-wasm-glue.ts:111`, `src/generator/js-wasm-glue.ts:158`, `src/generator/js-wasm-glue.ts:162`, `src/generator/js-wasm-glue.ts:197`, `src/generator/js-wasm-glue.ts:286`, `src/generator/js-wasm-glue.ts:300`).

### Missing or under-represented

- Structured control flow is absent from the opcode table: there are no block, loop, conditional, branch, branch-table, select, or unreachable entries, and generated bodies are linear call/arithmetic sequences ending in `end` (`src/generator/wasm-builder.ts:92`, `src/generator/js-wasm-glue.ts:61`, `src/generator/js-wasm-glue.ts:159`, `src/generator/js-wasm-glue.ts:242`).
- Reference types are limited to value constants and imported-table descriptors: there are no reference instructions, local table definitions, element segments, or table operations, and `call_indirect` is listed but not generated (`src/generator/wasm-builder.ts:18`, `src/generator/wasm-builder.ts:54`, `src/generator/wasm-builder.ts:95`, `src/generator/wasm-builder.ts:132`, `src/generator/wasm-builder.ts:272`).
- Multiple-memory behavior is only representable through repeated memory declarations and explicit data-segment indices; indexing is not import-aware, and no glue template generates more than one memory or accesses a nonzero memory (`src/generator/wasm-builder.ts:137`, `src/generator/wasm-builder.ts:206`, `src/generator/wasm-builder.ts:213`, `src/generator/wasm-builder.ts:436`, `src/generator/js-wasm-glue.ts:267`).
- Bulk memory is absent because only active data segments are encoded and the opcode table has no memory-copy, memory-fill, memory-init, or data-drop operations; there is also no data-count section (`src/generator/wasm-builder.ts:81`, `src/generator/wasm-builder.ts:92`, `src/generator/wasm-builder.ts:431`, `src/generator/wasm-builder.ts:272`).
- SIMD is nominally represented by `V128` but has no vector instructions, vector constants, lane operations, or generated signatures (`src/generator/wasm-builder.ts:17`, `src/generator/wasm-builder.ts:92`, `src/generator/js-wasm-glue.ts:57`, `src/generator/js-wasm-glue.ts:157`, `src/generator/js-wasm-glue.ts:232`).
- Wasm exception handling is absent: the builder has no tag section or try/catch/throw instructions, while the throwing-import template covers only delivery of a JS exception through a Wasm call boundary (`src/generator/wasm-builder.ts:22`, `src/generator/wasm-builder.ts:29`, `src/generator/wasm-builder.ts:92`, `src/generator/js-wasm-glue.ts:158`, `src/generator/js-wasm-glue.ts:183`, `src/generator/js-wasm-glue.ts:197`).
- Tail calls, GC proposal types/instructions, the component model, shared-memory/atomic operations, memory64 limits, start functions, and local table/global definitions have no corresponding IR collections, section writers, or opcodes in this builder (`src/generator/wasm-builder.ts:12`, `src/generator/wasm-builder.ts:92`, `src/generator/wasm-builder.ts:132`, `src/generator/wasm-builder.ts:272`, `src/generator/wasm-builder.ts:368`).
- Non-`i32` scalar conversions and arithmetic, multi-value execution, richer local layouts, indirect calls, and memory/global/table imports and exports are not generated by the registered templates (`src/generator/wasm-builder.ts:92`, `src/generator/js-wasm-glue.ts:57`, `src/generator/js-wasm-glue.ts:157`, `src/generator/js-wasm-glue.ts:232`, `src/generator/js-wasm-glue.ts:375`).

## 5. Prioritized improvement list

1. Add typed instruction constructors plus opcode-specific immediate validation and automatic body termination, because the current `number[]` API leaves most malformed encodings detectable only by the consumer (`src/generator/wasm-builder.ts:36`, `src/generator/wasm-builder.ts:408`, `src/generator/wasm-builder.ts:420`).
2. Add table, element, and local-global sections with reference/table instructions and generated indirect-call paths, because these core index spaces are represented only partially and are absent from templates (`src/generator/wasm-builder.ts:54`, `src/generator/wasm-builder.ts:95`, `src/generator/wasm-builder.ts:132`, `src/generator/js-wasm-glue.ts:375`).
3. Generate a value-type matrix across `i32`, `i64`, `f32`, `f64`, references, multi-parameter, and multi-result signatures, because the declared type surface currently collapses to `i32` in every template (`src/generator/wasm-builder.ts:12`, `src/generator/js-wasm-glue.ts:57`, `src/generator/js-wasm-glue.ts:157`, `src/generator/js-wasm-glue.ts:232`).
4. Implement structured control-flow generation for blocks, loops, conditionals, branches, tables, and selects, because current bodies are short linear sequences (`src/generator/wasm-builder.ts:92`, `src/generator/js-wasm-glue.ts:61`, `src/generator/js-wasm-glue.ts:242`).
5. Make all index-returning APIs account for imported and local objects and validate references, limits, and duplicate export names before encoding, because memory indices can drift and other references are unchecked (`src/generator/wasm-builder.ts:163`, `src/generator/wasm-builder.ts:202`, `src/generator/wasm-builder.ts:206`, `src/generator/wasm-builder.ts:368`).
6. Extend memory generation to active/passive segments, bulk operations, multiple memories, growth, shared/atomic variants, and memory64, because the templates currently only declare one unused memory (`src/generator/wasm-builder.ts:106`, `src/generator/wasm-builder.ts:114`, `src/generator/wasm-builder.ts:431`, `src/generator/js-wasm-glue.ts:267`).
7. Add SIMD, exception-handling, tail-call, and GC feature families behind explicit feature configurations, because `v128` is only a type constant and the corresponding sections/opcodes are otherwise absent (`src/generator/wasm-builder.ts:17`, `src/generator/wasm-builder.ts:92`, `src/generator/wasm-builder.ts:272`).
8. Broaden glue scenarios to imported/exported tables, memories and globals, re-entrant and indirect calls, multiple instances, asynchronous APIs, and observable exception assertions, because all registered templates use synchronous single-module flows and mostly direct `i32` calls (`src/generator/js-wasm-glue.ts:75`, `src/generator/js-wasm-glue.ts:158`, `src/generator/js-wasm-glue.ts:209`, `src/generator/js-wasm-glue.ts:375`).
9. Centralize metadata schemas and derive call-site offsets from encoded instruction positions, because call-target encoding is duplicated and offsets are currently hard-coded from assumed instruction widths (`src/generator/wasm-builder.ts:246`, `src/generator/js-wasm-glue.ts:250`, `src/generator/js-wasm-glue.ts:330`).
