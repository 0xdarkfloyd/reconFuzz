# GC Templates and Tier-Up Harness Review

## 1. Structure map

### GC template framework

- `GcTemplate` exposes a stable `name` and `build(seed?)`, with each builder returning a `ReconfuzzProgram`; the shared helpers normalize the seed, create a seeded PRNG, select bounded integers, emit `gc()`, and reject loop bodies or counts outside `0..1000` (`src/generator/gc-templates.ts:23`, `src/generator/gc-templates.ts:28`, `src/generator/gc-templates.ts:31`, `src/generator/gc-templates.ts:36`, `src/generator/gc-templates.ts:40`, `src/generator/gc-templates.ts:47`, `src/generator/gc-templates.ts:54`, `src/generator/gc-templates.ts:58`).
- Every concrete builder returns a Babel `File` in `javascript`, an empty `wasm` and `includes` array, and engine flags; the exported registry instantiates all five templates (`src/generator/gc-templates.ts:158`, `src/generator/gc-templates.ts:239`, `src/generator/gc-templates.ts:358`, `src/generator/gc-templates.ts:446`, `src/generator/gc-templates.ts:556`, `src/generator/gc-templates.ts:565`).

### GC templates

- `WasmInstanceGcTemplate.build(seed)` selects 10-80 outer iterations, a GC cadence from 4/8/10/16, and 1-4 instances per iteration; it creates an eight-byte minimal Wasm module image, repeatedly constructs `WebAssembly.Module` and `WebAssembly.Instance`, reads `instance.exports`, catches construction errors, and periodically calls `gc()` (`src/generator/gc-templates.ts:79`, `src/generator/gc-templates.ts:82`, `src/generator/gc-templates.ts:84`, `src/generator/gc-templates.ts:91`, `src/generator/gc-templates.ts:105`, `src/generator/gc-templates.ts:118`, `src/generator/gc-templates.ts:123`, `src/generator/gc-templates.ts:132`, `src/generator/gc-templates.ts:138`, `src/generator/gc-templates.ts:146`). Its output requests native syntax and exposed GC even though this body contains no native intrinsic (`src/generator/gc-templates.ts:158`).
- `ArrayBufferDetachGcTemplate.build(seed)` selects 10-80 calls, a 64-8192-byte buffer, 1-6 `DataView`s, and GC cadence 3-16; each `stress()` call allocates the buffer/views, invokes `%ArrayBufferDetach(ab)`, catches the expected post-detach `getUint8(0)` failure, and the outer loop periodically calls `gc()` (`src/generator/gc-templates.ts:171`, `src/generator/gc-templates.ts:174`, `src/generator/gc-templates.ts:176`, `src/generator/gc-templates.ts:181`, `src/generator/gc-templates.ts:185`, `src/generator/gc-templates.ts:191`, `src/generator/gc-templates.ts:201`, `src/generator/gc-templates.ts:204`, `src/generator/gc-templates.ts:224`). The returned flags enable both required V8 facilities (`src/generator/gc-templates.ts:239`).
- `WeakCollectionGcTemplate.build(seed)` selects 10-80 iterations, graph depth 2-8, one or two child branches, 1-4 entries per iteration, and GC cadence 3-16; it keeps one `WeakMap` and `WeakSet` alive, constructs recursive object trees, stores each root as a weak key and `root.child` as a weak-set member, drops the strong root, and periodically calls `gc()` (`src/generator/gc-templates.ts:252`, `src/generator/gc-templates.ts:255`, `src/generator/gc-templates.ts:257`, `src/generator/gc-templates.ts:262`, `src/generator/gc-templates.ts:287`, `src/generator/gc-templates.ts:293`, `src/generator/gc-templates.ts:308`, `src/generator/gc-templates.ts:327`, `src/generator/gc-templates.ts:336`, `src/generator/gc-templates.ts:341`, `src/generator/gc-templates.ts:346`). The output needs only exposed GC (`src/generator/gc-templates.ts:358`).
- `FinalizationRegistryGcTemplate.build(seed)` selects 10-80 iterations, registration stride 1-4, unregister cadence 2-8, and GC cadence 3-16; it creates one registry whose cleanup callback calls `gc()`, conditionally registers a short-lived target with a numeric held value and object token, conditionally unregisters it, clears the target, and periodically forces GC (`src/generator/gc-templates.ts:371`, `src/generator/gc-templates.ts:374`, `src/generator/gc-templates.ts:376`, `src/generator/gc-templates.ts:381`, `src/generator/gc-templates.ts:385`, `src/generator/gc-templates.ts:396`, `src/generator/gc-templates.ts:398`, `src/generator/gc-templates.ts:401`, `src/generator/gc-templates.ts:407`, `src/generator/gc-templates.ts:410`, `src/generator/gc-templates.ts:417`, `src/generator/gc-templates.ts:428`, `src/generator/gc-templates.ts:434`). The output enables exposed GC (`src/generator/gc-templates.ts:446`).
- `SharedArrayBufferGcTemplate.build(seed)` selects 10-80 calls, a 64-4096-byte shared buffer, 1-4 atomic attempts, and GC cadence 3-16; each `test(iteration)` creates `sab`/`i32`, issues `Atomics.waitAsync(i32, 0, 0)`, may force GC, creates a separate `sab2`/`i32_2`, and calls `Atomics.notify(i32_2, 0, 1)` (`src/generator/gc-templates.ts:459`, `src/generator/gc-templates.ts:462`, `src/generator/gc-templates.ts:464`, `src/generator/gc-templates.ts:469`, `src/generator/gc-templates.ts:473`, `src/generator/gc-templates.ts:479`, `src/generator/gc-templates.ts:485`, `src/generator/gc-templates.ts:495`, `src/generator/gc-templates.ts:506`, `src/generator/gc-templates.ts:511`, `src/generator/gc-templates.ts:517`, `src/generator/gc-templates.ts:523`, `src/generator/gc-templates.ts:533`, `src/generator/gc-templates.ts:546`). The output enables exposed GC (`src/generator/gc-templates.ts:556`).

### Tier-up harness

- `buildTierUpHarness(topScope, rng, options)` accepts a mutable scope, caller-supplied RNG, and `maxLoopIterations`; it returns generated statements plus `--allow-natives-syntax` (`src/generator/tierup.ts:8`, `src/generator/tierup.ts:12`, `src/generator/tierup.ts:209`, `src/generator/tierup.ts:248`).
- The harness synthesizes one or two fresh single-argument functions, records each in `topScope`, and chooses a loop limit intended to be between 2 and `min(16, maxLoopIterations)` (`src/generator/tierup.ts:222`, `src/generator/tierup.ts:226`, `src/generator/tierup.ts:227`, `src/generator/tierup.ts:229`, `src/generator/tierup.ts:230`, `src/generator/tierup.ts:232`, `src/generator/tierup.ts:234`).
- Four target shapes are available: int32-coerced arithmetic accumulation, same-shape named-property load/store, packed-array indexed load plus `push`, and fixed-length `Int32Array` indexed load/store (`src/generator/tierup.ts:43`, `src/generator/tierup.ts:65`, `src/generator/tierup.ts:98`, `src/generator/tierup.ts:125`, `src/generator/tierup.ts:152`).
- For each target, three numeric arguments are selected from `[0, 1, -1, 2, 1.5, 3]`; the emitted `try` block declares the function, evaluates `%PrepareFunctionForOptimization(target)`, makes two warm-up calls, evaluates `%OptimizeFunctionOnNextCall(target)`, then makes the trigger call, while an empty catch absorbs ordinary exceptions (`src/generator/tierup.ts:17`, `src/generator/tierup.ts:184`, `src/generator/tierup.ts:189`, `src/generator/tierup.ts:196`, `src/generator/tierup.ts:197`, `src/generator/tierup.ts:203`, `src/generator/tierup.ts:238`).
- Native intrinsics are placed in direct-`eval` string literals so the surrounding AST remains parseable by ordinary JavaScript tooling, while the returned flag permits V8 to parse the strings at runtime (`src/generator/tierup.ts:170`, `src/generator/tierup.ts:174`, `src/generator/tierup.ts:177`, `src/generator/tierup.ts:248`).
- Despite the file header saying user-declared functions are occasionally optimized, the implementation intentionally restricts targets to newly synthesized functions because its comment documents an uncatchable V8 assertion risk for previously hot functions (`src/generator/tierup.ts:1`, `src/generator/tierup.ts:214`, `src/generator/tierup.ts:219`, `src/generator/tierup.ts:222`).

## 2. Correctness & robustness

- **CONFIRMED - SAB wait/notify do not pair.** `waitAsync` waits on `i32`, backed by `sab`, but `notify` targets `i32_2`, backed by a newly allocated `sab2`; consequently the notification cannot wake the waits created earlier in the same call (`src/generator/gc-templates.ts:473`, `src/generator/gc-templates.ts:479`, `src/generator/gc-templates.ts:495`, `src/generator/gc-templates.ts:511`, `src/generator/gc-templates.ts:517`, `src/generator/gc-templates.ts:533`). This contradicts the template's stated wait/notify intent and leaves the asynchronous results unobserved (`src/generator/gc-templates.ts:455`, `src/generator/gc-templates.ts:494`).
- **LIKELY - asynchronous wait resources can outlive the generated work.** The initial shared cell equals the expected value, `waitAsync` has no timeout, its result is discarded, and only a different buffer is notified; execution creates a bounded number of waits, but their completion is not bounded or awaited by the template (`src/generator/gc-templates.ts:473`, `src/generator/gc-templates.ts:479`, `src/generator/gc-templates.ts:485`, `src/generator/gc-templates.ts:495`, `src/generator/gc-templates.ts:523`, `src/generator/gc-templates.ts:546`). The file constructs no explicit rejection path, but it also attaches no completion or rejection observer to the returned async result (`src/generator/gc-templates.ts:492`).
- **CONFIRMED - tier-up loop limits mishandle small or malformed options.** `loopMax = Math.min(16, maxLoopIterations)` is passed as `max` to a helper that replaces any value below `min` with `min`, so `maxLoopIterations < 2` still emits two iterations instead of honoring the cap; `NaN` or non-integral runtime inputs can also produce `NaN` or a value above the requested fractional bound because the helper validates neither inputs nor integer bounds (`src/generator/tierup.ts:19`, `src/generator/tierup.ts:20`, `src/generator/tierup.ts:21`, `src/generator/tierup.ts:227`, `src/generator/tierup.ts:232`).
- **CONFIRMED - the tier-up RNG contract is unchecked.** `randInt` assumes the caller returns values in `[0,1)`, while `makeTargetDeclaration` immediately calls an array entry selected by the resulting shape; an RNG returning `1`, a negative value, or a non-finite value can select outside `0..3` and fail during generation (`src/generator/tierup.ts:19`, `src/generator/tierup.ts:21`, `src/generator/tierup.ts:152`, `src/generator/tierup.ts:157`, `src/generator/tierup.ts:162`, `src/generator/tierup.ts:211`, `src/generator/tierup.ts:231`).
- **LIKELY - scope metadata and emitted binding scope can diverge.** Each target is declared to `topScope` as a `var` function, but the actual `FunctionDeclaration` is nested inside a `try` block; later composition that trusts `topScope` could emit an outer reference whose availability depends on script mode and block-function semantics (`src/generator/tierup.ts:196`, `src/generator/tierup.ts:203`, `src/generator/tierup.ts:230`, `src/generator/tierup.ts:234`). All current harness references remain inside the same block, so the mismatch does not affect the block's own sequence (`src/generator/tierup.ts:197`, `src/generator/tierup.ts:203`).
- **CONFIRMED - probe failures and results are silent.** Every tier-up sequence is wrapped in an empty catch, every generated target call is an expression statement whose return value is discarded, and there is no optimization-status query or pre/post result comparison (`src/generator/tierup.ts:166`, `src/generator/tierup.ts:184`, `src/generator/tierup.ts:203`). Unsupported intrinsics, target exceptions, and semantic result changes therefore leave no evidence in `TierUpResult`, which contains only statements and flags (`src/generator/tierup.ts:12`, `src/generator/tierup.ts:170`, `src/generator/tierup.ts:248`).
- **CONFIRMED - GC generation is bounded.** The shared loop helper rejects counts above 1000, while every outer loop is sampled in `10..80`; nested Wasm instances, weak entries, SAB attempts, and view counts are capped at four, four, four, and six respectively, and graph recursion is capped at depth eight (`src/generator/gc-templates.ts:28`, `src/generator/gc-templates.ts:58`, `src/generator/gc-templates.ts:62`, `src/generator/gc-templates.ts:84`, `src/generator/gc-templates.ts:86`, `src/generator/gc-templates.ts:176`, `src/generator/gc-templates.ts:178`, `src/generator/gc-templates.ts:257`, `src/generator/gc-templates.ts:258`, `src/generator/gc-templates.ts:260`, `src/generator/gc-templates.ts:376`, `src/generator/gc-templates.ts:464`, `src/generator/gc-templates.ts:466`). The recursive weak graph is a tree rather than the circular graph described by the template comment because children never point to ancestors (`src/generator/gc-templates.ts:248`, `src/generator/gc-templates.ts:262`, `src/generator/gc-templates.ts:293`).
- **CONFIRMED - ordinary generated control flow has finite loops.** Tier-up bodies receive a nominal cap of 16 and their array induction is initialized at index zero before each iteration appends the next readable element; typed-array indexing masks offsets to `0..7` for an eight-element allocation (`src/generator/tierup.ts:32`, `src/generator/tierup.ts:102`, `src/generator/tierup.ts:116`, `src/generator/tierup.ts:120`, `src/generator/tierup.ts:129`, `src/generator/tierup.ts:140`, `src/generator/tierup.ts:143`, `src/generator/tierup.ts:227`). This bound is subject to the malformed-option issue above (`src/generator/tierup.ts:19`, `src/generator/tierup.ts:232`).
- **LIKELY - GC seed-to-parameters mapping is reproducible but intentionally aliases seeds.** Each build constructs its own RNG after mapping non-finite values to zero and truncating/wrapping finite values to uint32, so fractions and values congruent modulo `2^32` share a stream; reproducibility then depends on the imported `mulberry32` honoring its PRNG contract (`src/generator/gc-templates.ts:21`, `src/generator/gc-templates.ts:31`, `src/generator/gc-templates.ts:33`, `src/generator/gc-templates.ts:36`, `src/generator/gc-templates.ts:82`, `src/generator/gc-templates.ts:174`, `src/generator/gc-templates.ts:255`, `src/generator/gc-templates.ts:374`, `src/generator/gc-templates.ts:462`). Runtime collection timing remains nondeterministic for finalization and asynchronous waiting even when AST generation is reproducible (`src/generator/gc-templates.ts:381`, `src/generator/gc-templates.ts:385`, `src/generator/gc-templates.ts:495`).
- **LIKELY - tier-up output is deterministic only under external-state preconditions.** Random choices come from the caller's RNG and identifiers come from external `freshId`, while the function mutates the supplied `topScope`; identical nominal inputs need identical RNG state, identifier state, and scope state to yield identical ASTs (`src/generator/tierup.ts:6`, `src/generator/tierup.ts:209`, `src/generator/tierup.ts:211`, `src/generator/tierup.ts:226`, `src/generator/tierup.ts:230`, `src/generator/tierup.ts:234`, `src/generator/tierup.ts:240`).
- **LIKELY - engine-specific feature failures are inconsistently visible.** The detach intrinsic is outside the local `try` that protects only the detached view access, whereas Wasm construction, `waitAsync`, `notify`, and the full tier-up sequence have empty catches; unsupported features can therefore either terminate a template early or be silently treated as completed coverage (`src/generator/gc-templates.ts:118`, `src/generator/gc-templates.ts:142`, `src/generator/gc-templates.ts:201`, `src/generator/gc-templates.ts:204`, `src/generator/gc-templates.ts:492`, `src/generator/gc-templates.ts:530`, `src/generator/tierup.ts:203`). The returned flags cover `gc()` and native syntax where used, but do not feature-test the runtime constructs (`src/generator/gc-templates.ts:158`, `src/generator/gc-templates.ts:239`, `src/generator/gc-templates.ts:358`, `src/generator/gc-templates.ts:446`, `src/generator/gc-templates.ts:556`, `src/generator/tierup.ts:248`).
- **CONFIRMED - FinalizationRegistry does not exercise resurrection despite its comment.** The callback receives only a numeric held value, ignores it, and calls `gc()`; the target is cleared and no reference path restores it (`src/generator/gc-templates.ts:367`, `src/generator/gc-templates.ts:385`, `src/generator/gc-templates.ts:386`, `src/generator/gc-templates.ts:388`, `src/generator/gc-templates.ts:403`, `src/generator/gc-templates.ts:413`, `src/generator/gc-templates.ts:428`).
- **SPECULATIVE - direct `eval` may change what is being measured.** The two optimization requests are parsed and resolved through direct `eval` rather than represented as native-call AST nodes; although this keeps the surrounding program parseable, an engine's eval context or instrumentation could differ from a direct intrinsic call and should be validated empirically (`src/generator/tierup.ts:170`, `src/generator/tierup.ts:174`, `src/generator/tierup.ts:177`, `src/generator/tierup.ts:198`, `src/generator/tierup.ts:200`).

## 3. Coverage gaps

### GC coverage

- **Exercised:** synchronous Wasm module/instance churn, explicit `ArrayBuffer` detachment followed by a `DataView` access, weak-key/set-member churn over short-lived trees, finalizer registration/unregistration with GC in the callback, and SAB `waitAsync`/GC/notify calls (`src/generator/gc-templates.ts:105`, `src/generator/gc-templates.ts:201`, `src/generator/gc-templates.ts:204`, `src/generator/gc-templates.ts:308`, `src/generator/gc-templates.ts:381`, `src/generator/gc-templates.ts:396`, `src/generator/gc-templates.ts:485`, `src/generator/gc-templates.ts:506`, `src/generator/gc-templates.ts:523`).
- **Missing - `WeakRef` lifecycle patterns:** there is no `WeakRef` construction or `deref()` observation before/after collection, no temporary strong-retention phase, and no combined `WeakRef` plus `WeakMap`/`WeakSet` graph; the only weak constructs are `WeakMap`, `WeakSet`, and `FinalizationRegistry` (`src/generator/gc-templates.ts:287`, `src/generator/gc-templates.ts:290`, `src/generator/gc-templates.ts:381`, `src/generator/gc-templates.ts:565`).
- **Missing - richer finalization scheduling:** the registry uses one callback, numeric held values, ephemeral unregister tokens, and a synchronous allocation loop, with no explicit task/microtask turns, multiple registries, retained tokens, observable cleanup order, or callback-side allocation graph (`src/generator/gc-templates.ts:381`, `src/generator/gc-templates.ts:385`, `src/generator/gc-templates.ts:396`, `src/generator/gc-templates.ts:407`, `src/generator/gc-templates.ts:428`).
- **Missing - asynchronous GC phase coverage:** apart from an ignored `waitAsync` result, templates contain no `Promise`, `async` function, timer/task pump, or awaited completion around `gc()`, so collection/finalization across scheduling turns is not deliberately exercised (`src/generator/gc-templates.ts:54`, `src/generator/gc-templates.ts:385`, `src/generator/gc-templates.ts:434`, `src/generator/gc-templates.ts:492`).
- **Missing - collector-mode differentiation:** all templates use the same zero-argument `gc()` form and return only `--expose-gc` plus, where needed, native syntax; none distinguishes young-generation scavenging from major mark-sweep/compaction or deliberately schedules incremental/concurrent marking (`src/generator/gc-templates.ts:54`, `src/generator/gc-templates.ts:158`, `src/generator/gc-templates.ts:239`, `src/generator/gc-templates.ts:358`, `src/generator/gc-templates.ts:446`, `src/generator/gc-templates.ts:556`).
- **Missing - allocation-pressure diversity:** buffers are capped at 8192 bytes for `ArrayBuffer` and 4096 bytes for SAB, object graphs at depth eight, and outer loops at 80; there are no retained survivor cohorts, large-object allocations, mixed-size bursts, old-to-young strong-reference mutations, or explicit promotion phases (`src/generator/gc-templates.ts:176`, `src/generator/gc-templates.ts:177`, `src/generator/gc-templates.ts:257`, `src/generator/gc-templates.ts:258`, `src/generator/gc-templates.ts:376`, `src/generator/gc-templates.ts:464`, `src/generator/gc-templates.ts:465`).
- **Missing - standards-based transfer paths:** the buffer template uses only `%ArrayBufferDetach` and the SAB template creates buffers locally; there is no `ArrayBuffer.transfer`, structured cloning, worker, or `postMessage` transfer path (`src/generator/gc-templates.ts:181`, `src/generator/gc-templates.ts:201`, `src/generator/gc-templates.ts:469`, `src/generator/gc-templates.ts:511`).
- **Missing - meaningful SAB coordination:** waiting and notification use different buffers, no worker shares a buffer, and no atomic load/store/read-modify-write operations change the waited-on cell (`src/generator/gc-templates.ts:473`, `src/generator/gc-templates.ts:495`, `src/generator/gc-templates.ts:511`, `src/generator/gc-templates.ts:533`).
- **Missing - broader Wasm GC surfaces:** the Wasm bytes encode only a minimal empty module and the template performs synchronous module/instance construction; it does not cover Wasm GC reference types, memories/tables with external references, async compilation/instantiation, exports with live state, or code-tier lifecycle (`src/generator/gc-templates.ts:91`, `src/generator/gc-templates.ts:118`, `src/generator/gc-templates.ts:123`, `src/generator/gc-templates.ts:132`, `src/generator/gc-templates.ts:138`).

### Tier-up coverage

- **Exercised:** a generic V8 prepare/warm-up/optimize-next-call path over arithmetic, named property, packed array, and typed-array bodies, with direct calls and a small numeric argument pool containing integers and one fractional value (`src/generator/tierup.ts:17`, `src/generator/tierup.ts:43`, `src/generator/tierup.ts:65`, `src/generator/tierup.ts:98`, `src/generator/tierup.ts:125`, `src/generator/tierup.ts:184`, `src/generator/tierup.ts:197`).
- **Missing - tier identity and status:** the harness requests generic optimization but emits no tier-specific flags/intrinsics and no status query, so it neither selects nor distinguishes Maglev from TurboFan and cannot confirm that the trigger call entered an optimized tier (`src/generator/tierup.ts:170`, `src/generator/tierup.ts:198`, `src/generator/tierup.ts:200`, `src/generator/tierup.ts:248`).
- **Missing - deoptimization paths:** the warm-up and trigger arguments all come from the same numeric pool, object shapes are recreated from one literal site, and there is no post-optimization call with a deliberately incompatible type, map, bounds condition, detached buffer, exception, or dependency invalidation (`src/generator/tierup.ts:17`, `src/generator/tierup.ts:73`, `src/generator/tierup.ts:98`, `src/generator/tierup.ts:125`, `src/generator/tierup.ts:189`, `src/generator/tierup.ts:192`, `src/generator/tierup.ts:240`).
- **Missing - feedback diversity:** existing bodies cover arithmetic binary operations, named loads/stores, keyed loads/stores, and `Array.prototype.push`, but do not create polymorphic or megamorphic receiver maps, call targets, constructors, globals, prototype-chain cases, holes, dictionary elements, or mixed object/value types (`src/generator/tierup.ts:43`, `src/generator/tierup.ts:65`, `src/generator/tierup.ts:98`, `src/generator/tierup.ts:125`, `src/generator/tierup.ts:157`).
- **Missing - inlining:** synthesized targets do not call another synthesized JavaScript function; the only call inside any target body is the array shape's built-in `push`, so caller/callee inlining and deoptimization across an inlined frame are absent (`src/generator/tierup.ts:43`, `src/generator/tierup.ts:65`, `src/generator/tierup.ts:103`, `src/generator/tierup.ts:125`, `src/generator/tierup.ts:152`).
- **Missing - natural hotness and OSR:** only two warm-up calls precede a forced optimize-on-next-call request, loops are capped nominally at 16, and there is no long-running loop or on-stack replacement request (`src/generator/tierup.ts:189`, `src/generator/tierup.ts:197`, `src/generator/tierup.ts:200`, `src/generator/tierup.ts:227`).
- **Missing - existing-program composition:** only newly synthesized functions are selected even though `topScope` is supplied, so grammar-generated function shapes and their accumulated feedback are excluded from tier-up coverage (`src/generator/tierup.ts:209`, `src/generator/tierup.ts:214`, `src/generator/tierup.ts:219`, `src/generator/tierup.ts:222`).
- **Missing - semantic oracle:** return values from warm-up and optimized calls are discarded and exceptions are swallowed, preventing the harness itself from comparing baseline and optimized behavior (`src/generator/tierup.ts:166`, `src/generator/tierup.ts:189`, `src/generator/tierup.ts:192`, `src/generator/tierup.ts:203`).

## 4. Prioritized improvement list

1. Make SAB waits and notifications share the same buffer, add a finite timeout and completion observation, and optionally coordinate a worker; this converts currently disconnected calls into bounded atomic/GC interaction coverage (`src/generator/gc-templates.ts:473`, `src/generator/gc-templates.ts:495`, `src/generator/gc-templates.ts:511`, `src/generator/gc-templates.ts:533`).
2. Add an observable tier-up oracle: preserve baseline and optimized return values, query optimization status/tier, and report caught exceptions; the current harness discards results and absorbs all ordinary failures (`src/generator/tierup.ts:166`, `src/generator/tierup.ts:197`, `src/generator/tierup.ts:203`).
3. Add post-optimization type/map changes and explicit deopt checks across monomorphic, polymorphic, and megamorphic cases; current inputs are numeric and each property receiver comes from one literal shape (`src/generator/tierup.ts:17`, `src/generator/tierup.ts:73`, `src/generator/tierup.ts:189`, `src/generator/tierup.ts:240`).
4. Add `WeakRef`/`deref()` and multi-turn finalization scenarios with retained and released unregister tokens; present weak coverage has collections plus one synchronous registry pattern (`src/generator/gc-templates.ts:287`, `src/generator/gc-templates.ts:381`, `src/generator/gc-templates.ts:396`, `src/generator/gc-templates.ts:407`).
5. Parameterize GC phase and allocation shape with young/major collection modes, promotion cohorts, large objects, and old-to-young mutations; current tests use undifferentiated `gc()` and small bounded allocations (`src/generator/gc-templates.ts:54`, `src/generator/gc-templates.ts:177`, `src/generator/gc-templates.ts:258`, `src/generator/gc-templates.ts:465`).
6. Add standards-based `ArrayBuffer` transfer/structured-clone and shared-buffer worker cases while retaining the intrinsic detach case; current coverage reaches only `%ArrayBufferDetach` and local SAB allocations (`src/generator/gc-templates.ts:201`, `src/generator/gc-templates.ts:473`, `src/generator/gc-templates.ts:511`).
7. Split tier-up scenarios by tier and path, including natural hotness, OSR, Maglev/TurboFan selection where supported, and inlined caller/callee pairs; the current sequence has one generic forced optimization request and short loops (`src/generator/tierup.ts:184`, `src/generator/tierup.ts:197`, `src/generator/tierup.ts:200`, `src/generator/tierup.ts:227`).
8. Validate `maxLoopIterations` and RNG outputs at the harness boundary, defining behavior for caps below two; current arithmetic can exceed a small cap or construct invalid numeric AST inputs (`src/generator/tierup.ts:19`, `src/generator/tierup.ts:227`, `src/generator/tierup.ts:232`).
9. Align binding metadata with emitted lexical placement by moving declarations to the surrounding statement list or recording their block scope; the current top-scope `var` declaration describes a function emitted inside `try` (`src/generator/tierup.ts:196`, `src/generator/tierup.ts:203`, `src/generator/tierup.ts:234`).
10. Correct template descriptions or implementations for circular weak graphs, finalizer resurrection, and occasional user-function optimization so documentation matches generated behavior (`src/generator/gc-templates.ts:248`, `src/generator/gc-templates.ts:262`, `src/generator/gc-templates.ts:367`, `src/generator/gc-templates.ts:385`, `src/generator/tierup.ts:1`, `src/generator/tierup.ts:214`).
