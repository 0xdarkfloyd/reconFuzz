# TypeScript Jest Test-Suite Quality and Coverage Review

Scope: `tests/*.test.ts`, `src/generator/*.ts`, and `src/mutator/*.ts`. This is a static review; the suite was read but not executed.

Status terms used below:

- **TESTED**: the principal public behavior has focused assertions, although edge cases may remain.
- **PARTIAL**: some public behavior is exercised, but important branches or contracts are covered only incidentally or not at all.
- **UNTESTED**: there is no focused test of the module's public entry point; incidental execution through another module is noted separately.

## 1. Coverage map

### What the suite covers well

- The strongest generator test is the 300-seed, four-mode corpus check: it prints every case, parses it with the `v8intrinsic` plugin, and requires more than 150 distinct sources per mode (`tests/generator.test.ts:264-274`). A separate JS-only corpus requires all 512 seeded sources to be distinct and parseable (`tests/diversity.test.ts:50-58`).
- Generator replay is checked for all four modes, and `setSeed` is checked after advancing the stream (`tests/generator.test.ts:55-69`). Seeded source mutation replay is also checked (`tests/diversity.test.ts:68-73`).
- Several grammar families receive structural checks rather than text-only checks: class heritage and `super()` placement (`tests/classes.test.ts:22-54`), bounded control-flow shapes (`tests/control-flow.test.ts:75-128`), destructuring initializer compatibility (`tests/destructuring.test.ts:24-64`), optional-chain node kinds (`tests/optional-chaining.test.ts:19-35`), and selected type-hint constraints (`tests/type-hint-soundness.test.ts:28-56`).
- The AST mutator tests commonly require three useful properties together: changed output, deterministic replay under an injected RNG, and reparsing (`tests/mutator.test.ts:254-275`). Focused tests also protect loop controls, allocation lengths, and sign-leading numeric substitutions (`tests/mutator.test.ts:215-240`, `tests/mutator.test.ts:278-315`).
- Every registered JS/Wasm glue template is built, compiled, instantiated, and invoked through an exported function; the throwing-import case checks the propagated error (`tests/generator.test.ts:195-222`). Metadata custom sections are also retrieved from a compiled module (`tests/generator.test.ts:174-193`).
- Server coverage includes typed query validation, body-size rejection followed by another successful request, split UTF-8 chunks, lift success, and lift failure (`tests/server.test.ts:93-173`).

## 3. Missing property / invariant tests

The suite already covers three important examples that should not be duplicated: all four modes parse over 300 seeds (`tests/generator.test.ts:264-274`), same seed plus mode reproduces identical output (`tests/generator.test.ts:55-61`), and all four modes exceed a common diversity floor (`tests/generator.test.ts:264-274`). Weighted selection also has exact bucket examples and one realized heavy-weight distribution check (`tests/production-weights.test.ts:15-38`, `tests/production-weights.test.ts:53-82`). The missing properties are the broader contracts below.

1. **Generated-program config matrix:** for every mode and a matrix of feature switches, depth/statement/loop limits, and production-weight maps, every source over `N` seeds parses as a script with `v8intrinsic`; the current all-mode property uses only default config (`tests/generator.test.ts:264-274`).
2. **Mutation closure:** for each registered AST mutator, each mode, and `N` generated seeds, an eligible deterministic mutation prints and reparses; the current property uses one JS-only seed, the default random catalogue, and ten unseeded attempts (`tests/mutator.test.ts:32-41`).
3. **Seeded mutation determinism:** the same program, config, and RNG seed yields identical AST and Wasm bytes for every registered mutator, while a different seed yields at least `K` distinct outputs over `S` seeds; current replay covers aggregate AST mutation and only `bitFlip` for Wasm (`tests/mutator.test.ts:163-201`).
4. **No accidental sign-token merge:** after printing generated and numerically mutated ASTs, every lexical `++`/`--` token must correspond to an intended `UpdateExpression`, not adjacency between a binary operator and sign-leading literal. The current check rejects raw substrings only on one mutation fixture and cannot be applied to generated loops that legitimately contain `++` (`tests/mutator.test.ts:293-315`; `tests/control-flow.test.ts:108-117`).
5. **Binding soundness:** with `allowUndeclaredIdentifiers: false`, every referenced generated identifier resolves in Babel scope, no `let`/`const` binding is redeclared in one scope, and destructured bindings are visible only after their declaration; current tests prove later use can occur but do not resolve every reference (`tests/destructuring.test.ts:21-64`).
6. **Type-hint soundness matrix:** every `TypeHint` at depths 0 and `D` produces an expression satisfying an explicit structural predicate, including object keys for WeakMap/WeakSet, iterable delegated yields, bounded typed-array lengths, rejection-contained promises, and class construction rules. Current checks cover class node kinds, numeric comparisons, one boolean reachability property, and delegated iterability only (`tests/type-hint-soundness.test.ts:28-56`; `tests/generator.test.ts:277-300`).
7. **Production-weight laws:** equal positive weights match uniform bucket selection; scaling all weights leaves selection unchanged; a zero weight is never selected; invalid/empty/non-finite/negative weights are rejected; empirical frequencies are monotonic within tolerance for several vectors. Current tests cover equal weights, `[1,3,1]`, and `{number: 1000}` only (`tests/production-weights.test.ts:15-38`, `tests/production-weights.test.ts:53-82`).
8. **Feature-disable contracts:** disabling async, generators, classes, Wasm, or tier-up eliminates the corresponding AST nodes/flags over a seed corpus without reducing parseability below the configured minimum diversity. Only tier-up disablement has a negative assertion (`tests/generator.test.ts:123-129`).
9. **Template registry contract:** registered GC and glue names are unique; every template is reachable by generator selection over a bounded seed range; same seed yields identical source and bytes; every printed template parses; all embedded Wasm compiles; and flags match used intrinsics. Glue compilation is broad, while GC has only one focused template test (`tests/generator.test.ts:195-222`; `tests/gc-sab.test.ts:14-38`).
10. **Tier-up harness contract:** controlled RNG sequences produce one and two targets across all four shapes; each target is registered once; loop limits stay within configuration; and each block is exactly declaration, prepare, two warmups, optimize, trigger inside containment. Existing generator tests infer only text presence/order from printed output (`tests/generator.test.ts:107-155`).
11. **Wasm-builder validity:** every accepted combination in a supported type/import/function/memory/data/export/instruction matrix emits a module accepted by `WebAssembly.Module`; invalid type/export/data indices and immediates fail before bytes are returned. Current unit tests compile only indirectly through three templates and directly inspect two sections in one memory case (`tests/generator.test.ts:195-222`; `tests/wasm-builder.test.ts:57-73`).
12. **BinaryWriter round-trip:** unsigned and signed LEB128 boundary values, UTF-8 strings, and section lengths decode to the original values, and all out-of-domain values throw. Current direct validation covers only invalid `writeU32` values (`tests/wasm-builder.test.ts:75-81`).
13. **Printer substitution and immutability:** printing never changes the input AST/byte arrays; every valid sentinel resolves to exactly one copied byte array; invalid sentinels follow an explicit policy; helper/flag options affect only their own prefixes; and print-parse-print is stable modulo formatting. Current tests separately check a single matching and missing sentinel and default options (`tests/printer.test.ts:77-92`).
14. **Wasm-mutator containment:** all mutators preserve module name, input immutability, `Uint8Array` type, and the eight-byte header when present; printed programs always remain valid JavaScript. If mutated Wasm validity is a contract, compile every result; if malformed Wasm is intentional, assert that policy explicitly rather than treating byte change alone as success (`tests/mutator.test.ts:531-613`).
15. **Minimizer postcondition:** assuming the input satisfies the predicate, the result still satisfies it, is one-minimal with respect to top-level statement removal, preserves all non-body metadata, and leaves the input unchanged. Existing examples assert selected bodies but do not re-run the predicate or test removal of every surviving statement (`tests/mutator.test.ts:466-528`).
16. **Server transform round-trip:** `liftSource` is idempotent; embedded bytes and flags survive lift/mutate/crossover exactly; seeded transforms are deterministic; every successful transform parses; and body sizes `limit-1`, `limit`, and `limit+1` have exact responses. Lift idempotence alone is present, and only the over-limit case is exercised over HTTP (`tests/server.test.ts:116-141`; `tests/server.test.ts:180-187`).
17. **Server routing/lifecycle:** every path/method pair has an exact status/body/content-type contract, aborted and errored bodies settle once, and `startGeneratorServer(0)` can listen and close cleanly without retained handles. Current request tests do not cover start/close, content type, abort/error, 404, or successful HTTP crossover (`tests/server.test.ts:30-174`).

## 4. Fragile / flaky tests

- **Unseeded RNG:** the first mutator test constructs `new Mutator()` and calls it ten times without injecting or mocking RNG (`tests/mutator.test.ts:32-41`). It is both nondeterministic and shallow: the number and kind of mutations vary per run.
- **Module-global identifier state:** direct `JsGrammar` tests advance the shared `freshId` counter across a corpus (`tests/destructuring.test.ts:15-16`; `tests/optional-chaining.test.ts:7-8`, `tests/optional-chaining.test.ts:23-31`). Some replay tests compensate with `jest.isolateModules` or explicit resets (`tests/destructuring.test.ts:67-79`; `tests/optional-chaining.test.ts:38-43`), but feature tests can still depend on test order and newly added preceding generation.
- **Fixed-seed feature occurrence:** class members/heritage, destructuring forms, optional calls, edge values, and control-flow families must all happen inside hard-coded seed windows (`tests/classes.test.ts:8-54`; `tests/destructuring.test.ts:8-64`; `tests/optional-chaining.test.ts:19-35`; `tests/edge-values.test.ts:49-119`; `tests/control-flow.test.ts:65-128`). A valid production addition can shift RNG consumption and fail these tests without violating the intended feature probabilities.
- **Exact or implementation-coupled diversity:** requiring 512 distinct outputs from exactly 512 JS seeds is an exact-count assertion (`tests/diversity.test.ts:50-58`), while the four-mode threshold of 150/300 is tied to the present grammar and template counts (`tests/generator.test.ts:264-274`). Both are deterministic but fragile under intentional production rebalancing.
- **Distribution threshold coupled to recursion:** `{number: 1000}` must beat all other base productions combined by at least 5x (`tests/production-weights.test.ts:53-82`). Changes in recursive production accounting can alter this ratio even when weighted top-level selection remains correct.
- **Printed-source regex coupling:** tier-up order is inferred using exact intrinsic spelling and line-oriented regular expressions (`tests/generator.test.ts:131-155`), and the SharedArrayBuffer test depends on exact generated variable names and Babel formatting (`tests/gc-sab.test.ts:15-33`). AST assertions would survive formatting changes.
- **Mock call-order coupling:** several server mutation tests drive behavior by globally mocking a sequence of `Math.random` results (`tests/server.test.ts:217-226`; `tests/server.test.ts:286-300`). Adding one random draw inside mutation changes the selected path and invalidates the fixture.
- **Seed scan plus exact generated ID:** crossover scans only seeds 0-29 for a reference and separately requires `__v_42` for one seed (`tests/server.test.ts:303-345`). Grammar changes can move both events while collision avoidance and scope registration remain correct.
- **Large corpus timing:** the control-flow test generates and parses two 425-program corpora under a fixed 60-second timeout (`tests/control-flow.test.ts:6`, `tests/control-flow.test.ts:23-29`, `tests/control-flow.test.ts:63-68`). Runtime depends on CI CPU, Babel version, and grammar complexity.
- **Runtime-engine sensitivity:** template tests rely on the host's `WebAssembly.Module`, `Instance`, and custom-section behavior (`tests/generator.test.ts:18-30`, `tests/generator.test.ts:174-220`). Node/V8 version changes can alter support independently of TypeScript logic.
- **Golden byte encoding:** the exact 34-byte module assertion is high-signal for compatibility but intentionally brittle to any valid encoding or section-layout change (`tests/wasm-builder.test.ts:83-100`). Pairing it with semantic decoding/compilation would distinguish compatible refactors from regressions.
