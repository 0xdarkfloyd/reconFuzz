# Runner Detection, Corpus, Scheduling, and Coverage Review

## 1. Structure Map

- **Outcome classification.** `Detector.detect()` concatenates stdout and stderr for retention and hashing, classifies stderr first, falls back to stdout only when stderr has no recognized signature, and independently checks stderr for sanitizer output. Signature order is sanitizer first, then the ordered diagnostic table, then three signal-like text fragments. (`src/runner/detector.py:46`, `src/runner/detector.py:91`, `src/runner/detector.py:122`, `src/runner/detector.py:178`)
- **Status gating and labels.** A negative, non-timeout return code is the ordinary abnormal-outcome gate; a sanitizer marker plus any nonzero, non-timeout return code is a second gate. Flag-induced markers suppress the outcome, timeouts take precedence, and every non-admitted outcome is normalized to class `NONE`. (`src/runner/detector.py:130`, `src/runner/detector.py:132`, `src/runner/detector.py:152`, `src/runner/detector.py:161`)
- **Stack-hash construction.** `_stack_hash()` takes up to five eligible frames, normalizes hexadecimal addresses, reduces native C-stack records to symbols or module-relative offsets, and otherwise hashes up to eight normalized signature lines; the SHA-256 result is truncated to 16 hexadecimal characters. (`src/runner/detector.py:196`, `src/runner/detector.py:206`, `src/runner/detector.py:210`, `src/runner/detector.py:224`, `src/runner/detector.py:226`, `src/runner/detector.py:244`)
- **Outcome deduplication.** The detector supplies the class and stack hash, while `CorpusManager` forms a `class:stack_hash` key; normal fallback seeds and abnormal outcomes have separate seen-key sets, and metadata preloading carries those sets across runs. (`src/runner/detector.py:168`, `src/runner/corpus_manager.py:86`, `src/runner/corpus_manager.py:100`, `src/runner/corpus_manager.py:128`, `src/runner/corpus_manager.py:214`)
- **Seed model.** `Seed` stores identity, source, flags, outcome class, stack and coverage hashes, energy, timestamp, and an optional in-memory bitmap; serialization intentionally omits source and the bitmap, while both full and metadata-only iterators reconstruct records from each directory's `meta.json`. (`src/runner/corpus_manager.py:17`, `src/runner/corpus_manager.py:29`, `src/runner/corpus_manager.py:33`, `src/runner/corpus_manager.py:44`, `src/runner/corpus_manager.py:242`, `src/runner/corpus_manager.py:261`)
- **Seed admission.** In `gain` mode, a supplied bitmap is admitted on any bit absent from the local union and merged after persistence; otherwise an unseen coverage hash is the key, with class plus stack hash as the last fallback. (`src/runner/corpus_manager.py:136`, `src/runner/corpus_manager.py:149`, `src/runner/corpus_manager.py:153`, `src/runner/corpus_manager.py:158`, `src/runner/corpus_manager.py:169`, `src/runner/corpus_manager.py:177`)
- **Persistence and IDs.** Seed and outcome directories use the requested ID when free and append numeric suffixes on sequential collisions; `testcase.js` is written before `meta.json`, and iteration treats the directory name as the authoritative ID. (`src/runner/corpus_manager.py:162`, `src/runner/corpus_manager.py:214`, `src/runner/corpus_manager.py:229`, `src/runner/corpus_manager.py:242`, `src/runner/corpus_manager.py:256`)
- **Scheduling.** `assign_energy()` starts with base energy, adds bonuses for classes other than `NONE`/`UNKNOWN`/`TIMEOUT`, for the presence of a coverage hash, and for supplied depth; `select()` recomputes those energies and draws proportionally from their sum. (`src/runner/scheduler.py:12`, `src/runner/scheduler.py:37`, `src/runner/scheduler.py:42`, `src/runner/scheduler.py:44`, `src/runner/scheduler.py:47`, `src/runner/scheduler.py:50`, `src/runner/scheduler.py:53`)
- **Shared coverage union.** The parent creates and optionally restores a shared-memory region, workers attach by name, and `check_and_merge()` snapshots the requested prefix, tests for any new bit, then ORs the bitmap byte by byte. Persistence writes the payload prefix to a sibling temporary file, synchronizes it, and atomically replaces the union file. (`src/runner/coverage_union.py:26`, `src/runner/coverage_union.py:37`, `src/runner/coverage_union.py:45`, `src/runner/coverage_union.py:60`, `src/runner/coverage_union.py:68`, `src/runner/coverage_union.py:82`, `src/runner/coverage_union.py:86`, `src/runner/coverage_union.py:90`, `src/runner/coverage_union.py:102`)

## 2. Correctness & Robustness

Confidence labels describe what can be established from these four files alone.

- **CONFIRMED - shared-union lost-update race.** `buf[i] |= byte` is an unsynchronized read-modify-write; two workers setting different bits in the same byte can both read the old value and the later store can remove the earlier worker's bit. This contradicts the stated monotonic/no-lost-edge invariant and can make later admission and persistence observe an incomplete union. (`src/runner/coverage_union.py:9`, `src/runner/coverage_union.py:68`, `src/runner/coverage_union.py:78`, `src/runner/coverage_union.py:86`)
- **CONFIRMED - stackless semantic over-merge.** When no eligible frame exists, recognized outcomes hash only the matched title, not the surrounding report; generic titles such as `ASSERT...FAILED`, `buffer-overflow`, a sanitizer header, or `signal-like abort` therefore collapse same-class reports with different details. Empty-output negative returns all use class `UNKNOWN` and signature `unknown`, so they collapse as well. (`src/runner/detector.py:62`, `src/runner/detector.py:68`, `src/runner/detector.py:91`, `src/runner/detector.py:188`, `src/runner/detector.py:194`, `src/runner/detector.py:226`, `src/runner/detector.py:231`, `src/runner/corpus_manager.py:128`, `src/runner/corpus_manager.py:214`)
- **LIKELY - frame identity can both merge and split incorrectly.** Only the first five eligible V8/Builtins or native-path frames are retained, so differences below that prefix or exclusively in other frames disappear; conversely, whole `#` lines retain every non-address field, and stdout precedes stderr in the scan, so variable or program-generated frame-like text can produce distinct hashes for the same underlying outcome. (`src/runner/detector.py:123`, `src/runner/detector.py:196`, `src/runner/detector.py:201`, `src/runner/detector.py:206`, `src/runner/detector.py:210`, `src/runner/detector.py:224`)
- **CONFIRMED - successful diagnostic-looking output is gated correctly.** A zero return code cannot satisfy either outcome gate, and the final class becomes `NONE`; likewise, ordinary signature-looking text with a positive nonzero code is ignored unless it matches the sanitizer expression. (`src/runner/detector.py:127`, `src/runner/detector.py:130`, `src/runner/detector.py:152`, `src/runner/detector.py:153`, `src/runner/detector.py:165`)
- **LIKELY - sanitizer text has weaker provenance than other signatures.** Any matching stderr marker combined with any nonzero code satisfies `sanitizer_abort`, without requiring a negative native status; marker-shaped application output followed by an ordinary nonzero exit can therefore be retained as a sanitizer outcome. (`src/runner/detector.py:91`, `src/runner/detector.py:130`, `src/runner/detector.py:153`, `src/runner/detector.py:156`)
- **LIKELY - benign-marker precedence can hide a simultaneous abnormal outcome.** In the absence of a sanitizer marker, any benign-pattern match in stderr suppresses even a negative return code, without checking that the benign line is the primary diagnostic or that no second diagnostic is present. (`src/runner/detector.py:103`, `src/runner/detector.py:132`, `src/runner/detector.py:152`, `src/runner/detector.py:156`, `src/runner/detector.py:163`)
- **SPECULATIVE - native status handling may be representation-dependent.** Non-sanitizer native outcomes are accepted only when `returncode < 0`; an execution layer that represents a signal as a positive shell-style status would be normalized to `NONE` despite recognized diagnostic text. The result-wrapper contract is outside the reviewed files, so this remains conditional. (`src/runner/detector.py:127`, `src/runner/detector.py:152`, `src/runner/detector.py:165`)
- **LIKELY - gain admission is sensitive to background coverage jitter.** One previously unseen bit is sufficient for immediate retention and permanent union merge, with no repeat measurement or stability threshold; a transient bit can retain an unstable seed and then cause a later stable seed whose only gain is that bit to be dropped. (`src/runner/corpus_manager.py:149`, `src/runner/corpus_manager.py:169`, `src/runner/corpus_manager.py:177`, `src/runner/corpus_manager.py:187`, `src/runner/coverage_union.py:68`, `src/runner/coverage_union.py:82`)
- **LIKELY - directory collision handling is not safe for concurrent writers.** `_unique_dir()` separates sequential duplicate IDs, but the existence check, `mkdir(exist_ok=True)`, and direct file writes are not one atomic reservation; concurrent writers selecting the same candidate can overwrite each other's `testcase.js` and `meta.json`. (`src/runner/corpus_manager.py:162`, `src/runner/corpus_manager.py:164`, `src/runner/corpus_manager.py:167`, `src/runner/corpus_manager.py:220`, `src/runner/corpus_manager.py:229`)
- **CONFIRMED - persisted energy is disconnected from scheduling.** `Seed.energy` is serialized and restored, but `Scheduler.select()` recomputes energy without consulting it; additionally, `select()` never supplies depth, so `depth_bonus` has no effect on selection through this API. (`src/runner/corpus_manager.py:27`, `src/runner/corpus_manager.py:40`, `src/runner/corpus_manager.py:53`, `src/runner/scheduler.py:37`, `src/runner/scheduler.py:50`, `src/runner/scheduler.py:58`)
- **CONFIRMED - gain-only novelty is invisible to the coverage bonus.** The scheduler tests only `coverage_hash`, while gain admission can retain a seed using only `coverage_bitmap`; that bitmap is not persisted, so such a seed receives no coverage bonus either immediately or after reload unless another component also supplies a hash. (`src/runner/corpus_manager.py:26`, `src/runner/corpus_manager.py:29`, `src/runner/corpus_manager.py:39`, `src/runner/corpus_manager.py:149`, `src/runner/scheduler.py:47`)
- **CONFIRMED - bitmap-size validation is inconsistent.** `CorpusManager` rejects input longer than `FUZZILLI_SHM_SIZE - 4`, but `CoverageUnion.check_and_merge()` permits input up to the full shared region; up to four extra bytes can influence in-memory admission and are then omitted from the payload-only saved file. Both paths also accept shorter bitmaps without detecting truncation. (`src/runner/corpus_manager.py:89`, `src/runner/corpus_manager.py:177`, `src/runner/coverage_union.py:29`, `src/runner/coverage_union.py:40`, `src/runner/coverage_union.py:74`, `src/runner/coverage_union.py:109`)
- **LIKELY - union durability can lag indefinitely after the last update.** `CorpusManager` sets a dirty flag but only attempts persistence during merge, so an update throttled inside the five-second window has no timer or public final-flush path in this class; direct writes and swallowed errors add partial-file and silent-staleness risks. `CoverageUnion` uses atomic replacement, but advances its throttle timestamp before a failed save, delaying retry. (`src/runner/corpus_manager.py:187`, `src/runner/corpus_manager.py:192`, `src/runner/corpus_manager.py:195`, `src/runner/corpus_manager.py:205`, `src/runner/corpus_manager.py:207`, `src/runner/corpus_manager.py:209`, `src/runner/coverage_union.py:90`, `src/runner/coverage_union.py:94`, `src/runner/coverage_union.py:100`, `src/runner/coverage_union.py:113`)
- **SPECULATIVE - digest collisions remain possible at large scale.** Deduplication uses only the first 64 bits of SHA-256, and class separation protects only cross-class collisions; sufficiently large same-class collections have a birthday-collision risk independent of the more immediate semantic over-merging above. (`src/runner/detector.py:244`, `src/runner/corpus_manager.py:128`, `src/runner/corpus_manager.py:214`)

## 3. Effectiveness Gaps

- **Distinct outcomes can be collapsed by classification-derived identity.** Generic stackless titles, empty `UNKNOWN` output, the five-frame cutoff, and omission of nonmatching frames all remove discriminating context before the dedup key is built. (`src/runner/detector.py:178`, `src/runner/detector.py:196`, `src/runner/detector.py:206`, `src/runner/detector.py:224`, `src/runner/detector.py:226`, `src/runner/corpus_manager.py:128`)
- **Distinct seeds can be dropped by coverage-first admission.** A supplied bitmap in `gain` mode or any coverage hash takes precedence over class/stack identity, so an outcome-distinct seed with no new bit, or with an already-seen exact coverage hash, is rejected before its outcome identity is considered. (`src/runner/corpus_manager.py:149`, `src/runner/corpus_manager.py:153`, `src/runner/corpus_manager.py:157`)
- **Coverage-free normal seeds share a coarse fallback.** A frame-free successful execution is normalized to title `no crash`, which produces the same stack hash; without bitmap or coverage hash, `class:stack_hash` admission therefore retains only the first such seed regardless of source or flags. (`src/runner/detector.py:165`, `src/runner/detector.py:226`, `src/runner/detector.py:231`, `src/runner/corpus_manager.py:21`, `src/runner/corpus_manager.py:23`, `src/runner/corpus_manager.py:157`)
- **Non-incremental seeds can be retained in hash mode.** Any unseen, nonempty supplied coverage hash is admitted even when it adds no edge to the global union, so nondeterministic bitmap differences or alternate encodings can expand the corpus without incremental reach. (`src/runner/corpus_manager.py:74`, `src/runner/corpus_manager.py:76`, `src/runner/corpus_manager.py:153`, `src/runner/corpus_manager.py:171`)
- **Outcome text can retain non-distinct entries.** Sanitizer-shaped stderr plus an ordinary nonzero exit is sufficient for retention, and broad benign-marker precedence can move the opposite direction by suppressing an otherwise distinct negative-status outcome. (`src/runner/detector.py:130`, `src/runner/detector.py:132`, `src/runner/detector.py:153`, `src/runner/detector.py:156`)
- **Racy union updates can both duplicate and defer admission.** Concurrent snapshots permit two workers to accept the same new bit, while a lost same-byte update removes knowledge already observed and permits later re-admission; the union is therefore neither a strict deduplicator nor a reliably monotonic admission history. (`src/runner/coverage_union.py:68`, `src/runner/coverage_union.py:82`, `src/runner/coverage_union.py:84`, `src/runner/coverage_union.py:86`)
- **Scheduling uses coarse binary signals.** Selection depends only on three exact excluded class strings and whether `coverage_hash` is truthy; it does not use bitmap rarity, measured incremental gain, timestamp, stored energy, source size, prior selection count, execution cost, or outcome recurrence, although some corresponding seed metadata already exists. (`src/runner/corpus_manager.py:21`, `src/runner/corpus_manager.py:26`, `src/runner/corpus_manager.py:27`, `src/runner/corpus_manager.py:28`, `src/runner/scheduler.py:37`, `src/runner/scheduler.py:44`, `src/runner/scheduler.py:47`, `src/runner/scheduler.py:58`)
- **Unknown negative-status outcomes are under-prioritized.** The detector can retain a negative-status execution with class `UNKNOWN`, but the scheduler explicitly excludes `UNKNOWN` from its outcome bonus, losing the distinction between retained unknown outcomes and ordinary `NONE` seeds. (`src/runner/detector.py:152`, `src/runner/detector.py:156`, `src/runner/detector.py:194`, `src/runner/scheduler.py:44`)
- **Metadata quality is not validated at load time.** `cast()` performs no runtime validation, so malformed types can enter the corpus iterator; exact string comparisons and truthiness in energy assignment can then silently assign unintended weights rather than rejecting or normalizing the record. (`src/runner/corpus_manager.py:44`, `src/runner/corpus_manager.py:47`, `src/runner/corpus_manager.py:53`, `src/runner/corpus_manager.py:257`, `src/runner/corpus_manager.py:275`, `src/runner/scheduler.py:44`, `src/runner/scheduler.py:47`)

## 4. Prioritized Improvement List

1. Make shared-union check-and-merge linearizable, using an interprocess lock or atomic word OR, because current same-byte races can lose edge history and invalidate gain admission. (`src/runner/coverage_union.py:68`, `src/runner/coverage_union.py:82`, `src/runner/coverage_union.py:86`)
2. Build stackless identities from a canonicalized diagnostic block containing class, primary message, summary/location, and stable context, because hashing generic matched titles collapses distinct reports. (`src/runner/detector.py:178`, `src/runner/detector.py:226`, `src/runner/detector.py:231`)
3. Restrict frame extraction to the actual diagnostic stack, normalize every retained field, and add controlled lower-stack information, because the current five-frame scan can ingest stdout-like frames and omit the only distinguishing frame. (`src/runner/detector.py:123`, `src/runner/detector.py:201`, `src/runner/detector.py:206`, `src/runner/detector.py:224`)
4. Separate outcome identity from coverage admission and retain outcome-novel seeds even without coverage gain, because the current coverage-first branches never consult class/stack identity. (`src/runner/corpus_manager.py:149`, `src/runner/corpus_manager.py:153`, `src/runner/corpus_manager.py:157`)
5. Require corroborating status/channel evidence for sanitizer and benign classifications, because marker presence alone can respectively promote or suppress an outcome. (`src/runner/detector.py:130`, `src/runner/detector.py:132`, `src/runner/detector.py:153`, `src/runner/detector.py:156`)
6. Recheck candidate gain for stability before permanently merging it, or record confidence/frequency, because a single transient bit currently determines both retention and future rejection. (`src/runner/corpus_manager.py:149`, `src/runner/corpus_manager.py:169`, `src/runner/coverage_union.py:68`)
7. Reserve persistence directories atomically and write testcase/metadata through atomic renames, because the current existence-check/write sequence permits concurrent overwrite and interrupted entries. (`src/runner/corpus_manager.py:162`, `src/runner/corpus_manager.py:164`, `src/runner/corpus_manager.py:220`, `src/runner/corpus_manager.py:229`)
8. Define one durable novelty field and use it consistently in scheduling, then wire stored energy and depth into `select()`, because gain-only seeds miss the coverage bonus and two advertised energy inputs do not affect selection. (`src/runner/corpus_manager.py:26`, `src/runner/corpus_manager.py:27`, `src/runner/corpus_manager.py:149`, `src/runner/scheduler.py:37`, `src/runner/scheduler.py:47`, `src/runner/scheduler.py:58`)
9. Add rarity, execution-cost, age, and selection-history feedback to energy calculation, because the current weighting is a static class/coverage-hash presence test. (`src/runner/scheduler.py:37`, `src/runner/scheduler.py:42`, `src/runner/scheduler.py:44`, `src/runner/scheduler.py:47`, `src/runner/scheduler.py:58`)
10. Enforce exactly one payload bitmap size and provide an explicit final durable flush with surfaced write errors, because size handling differs and throttled state can remain unsaved. (`src/runner/corpus_manager.py:177`, `src/runner/corpus_manager.py:195`, `src/runner/coverage_union.py:29`, `src/runner/coverage_union.py:74`, `src/runner/coverage_union.py:90`)
11. Validate loaded metadata against the `Seed` schema and normalize outcome-class values before scheduling, because runtime casts do not protect energy bookkeeping from malformed records. (`src/runner/corpus_manager.py:44`, `src/runner/corpus_manager.py:257`, `src/runner/corpus_manager.py:275`, `src/runner/scheduler.py:44`)
12. Store a longer digest or a secondary canonical signature for collision resolution after semantic deduplication is fixed, because the current persisted identity is only 64 bits. (`src/runner/detector.py:244`, `src/runner/corpus_manager.py:128`)
