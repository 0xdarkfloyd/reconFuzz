# `scripts/fuzz.py` Engineering Review

Scope: dry source review of the campaign orchestrator only. Conclusions that depend on imported implementations are explicitly qualified.

## 1. Structure map

- **CLI and validation.** The parser exposes the runtime binary and corpus/finding directories; finite or continuous iteration count; batch and worker counts; generation mode and seed; execution timeout; scheduler configuration; replay and crossover probabilities; admission policy; and execution backend. Counts are constrained to non-negative integers and probabilities to `[0, 1]`; timeout and seed receive no additional validation here (`scripts/fuzz.py:51-62`, `scripts/fuzz.py:81-177`).
- **Top-level initialization.** `main()` parses arguments, constructs the scheduler, detects dry-run and shared-memory coverage support, may change the requested REPRL backend to process mode, creates the optional shared coverage union and the parent-owned `CorpusManager`, and starts one generator daemon before creating workers (`scripts/fuzz.py:407-455`).
- **Worker initialization.** Each non-dry worker attaches the shared union when supplied, creates one persistent `ReprlRunner` or one reusable `D8Wrapper`, and wraps it in a `Harness`; dry-run workers intentionally leave the harness unset (`scripts/fuzz.py:237-264`).
- **Worker loop unit.** `worker_task()` derives an iteration seed, makes the replay transformation choice, loads a selected corpus testcase when available, otherwise requests fresh source, runs the harness, applies the worker-side admission prefilter, and returns a compact result to the parent. In dry-run mode it returns a synthetic `Seed` without evaluation (`scripts/fuzz.py:317-391`).
- **Parent versus worker responsibilities.** The parent owns replay selection, task submission, completion/error accounting, persistence, cache invalidation, periodic union snapshots, daemon restart checks, and shutdown; workers own source acquisition/transformation, execution, detection, and REPRL+gain novelty checks (`scripts/fuzz.py:493-608`, `scripts/fuzz.py:237-314`).
- **Daemon helpers.** `/generate` is a GET with mode and optional seed and raises `RuntimeError` on transport/decoding failure; `/mutate` and `/crossover` are POSTs and return their input unchanged on the same failure classes (`scripts/fuzz.py:180-223`). The daemon is launched with an 8 GiB Node heap, checked once after a fixed one-second delay, and later restarted only after its process has exited (`scripts/fuzz.py:447-455`, `scripts/fuzz.py:526-542`).
- **Replay/crossover dispatch.** The parent probabilistically attaches a scheduler-selected `replay_id` to each submitted task. The worker chooses crossover versus mutation, treats exact source equality as a no-op, and requests a fresh program instead of evaluating that unchanged corpus source (`scripts/fuzz.py:501-523`, `scripts/fuzz.py:339-376`).
- **Scheduler wiring.** Optional YAML is unpacked into `SchedulerConfig`; each replay decision calls `scheduler.select()` over cached seed metadata and passes only the selected ID to the worker (`scripts/fuzz.py:393-404`, `scripts/fuzz.py:501-520`).
- **Seed-list cache.** Metadata is loaded lazily on the first eligible replay choice, retained across submissions, and invalidated only after `corpus.add_seed()` reports success in either evaluated or dry-run handling (`scripts/fuzz.py:470-470`, `scripts/fuzz.py:501-509`, `scripts/fuzz.py:574-589`).
- **Flag merging.** A testcase's first `// Flags:` line is tokenized; replay in process mode falls back to `meta.json` when the source has no header, then appends newly introduced transformed-source flags without duplicates while preserving first occurrence order (`scripts/fuzz.py:65-78`, `scripts/fuzz.py:345-375`).
- **Execution mode selection.** REPRL is the default and uses only `FUZZING_FLAGS`; process mode accepts testcase flags. A requested REPRL run falls back to process mode when shared-memory coverage probing fails (`scripts/fuzz.py:28-48`, `scripts/fuzz.py:167-175`, `scripts/fuzz.py:248-259`, `scripts/fuzz.py:332-334`, `scripts/fuzz.py:419-430`).
- **Corpus/finding persistence.** Workers never persist results. The parent routes detected findings to `add_crash()` and other returned seeds to `add_seed()` through one `CorpusManager`; the shared union is saved periodically and forced to disk at normal/interrupted loop exit (`scripts/fuzz.py:443-445`, `scripts/fuzz.py:574-597`, `scripts/fuzz.py:627-637`).
- **Concurrency and shutdown.** A fork-based `ProcessPoolExecutor` maintains a sliding in-flight window and replenishes it after each completion. Worker SIGTERM closes a persistent REPRL runner before immediate exit; parent exception and interrupt paths cancel queued work, terminate workers, and terminate the daemon (`scripts/fuzz.py:475-499`, `scripts/fuzz.py:511-552`, `scripts/fuzz.py:267-293`, `scripts/fuzz.py:609-660`).

## 2. Correctness & robustness

| Confidence | Topic | Assessment |
|---|---|---|
| **CONFIRMED** | Seed-list invalidation | Both evaluated and dry-run admission branches set `seed_list_cache = None` only when `add_seed()` succeeds, so the next eligible replay choice reloads metadata and can include the new seed (`scripts/fuzz.py:501-509`, `scripts/fuzz.py:574-589`). Already-submitted tasks retain their earlier choices because replay IDs are bound at submission (`scripts/fuzz.py:511-523`). |
| **CONFIRMED** | No-op transformation fallback | Mutation/crossover transport failures return the original string, and exact equality triggers fresh generation; the returned `is_replay=False` also prevents counting the fallback as replay (`scripts/fuzz.py:195-223`, `scripts/fuzz.py:358-369`). Empty or unreadable corpus source also falls through to generation rather than evaluation (`scripts/fuzz.py:339-345`, `scripts/fuzz.py:378-382`). |
| **LIKELY** | Semantic no-op detection | Equality is byte-for-byte only, so a transformation that changes formatting or comments while preserving behavior still consumes evaluation budget as a replay (`scripts/fuzz.py:346-376`). |
| **CONFIRMED** | Flag honoring | Fresh and replayed programs pass discovered flags only when the runner is not `ReprlRunner`; process-mode replay merges parent metadata/header flags with transformed-source flags, while REPRL receives the fixed worker defaults (`scripts/fuzz.py:248-259`, `scripts/fuzz.py:332-375`, `scripts/fuzz.py:378-382`). |
| **LIKELY** | Flag metadata robustness | `list(metadata.get("flags", []))` does not validate that metadata flags are a list of strings; for example, a string becomes a list of characters and malformed elements reach the runner (`scripts/fuzz.py:350-357`, `scripts/fuzz.py:375-375`). |
| **CONFIRMED** | Daemon exit handling | Startup catches a daemon that exits within the initial delay, and task exceptions trigger an exit-status check plus restart; periodic successful-result handling performs the same watchdog check (`scripts/fuzz.py:447-455`, `scripts/fuzz.py:526-542`, `scripts/fuzz.py:554-568`, `scripts/fuzz.py:593-600`). |
| **CONFIRMED** | Live-but-unresponsive daemon gap | Requests can block for 30 seconds, but restart is conditional only on `daemon_proc.poll()` reporting exit. A live process that is unready, wedged, or repeatedly rejects requests is left in place and continues producing worker errors (`scripts/fuzz.py:186-190`, `scripts/fuzz.py:198-207`, `scripts/fuzz.py:214-223`, `scripts/fuzz.py:526-542`). |
| **CONFIRMED** | Finite-run accounting on task error | Iteration IDs are consumed on submission, while `executed` advances only on successful futures. The error path calls `submit_next()`, but finite mode refuses once the configured ID range is exhausted, so a run may report fewer successful iterations than `--iterations` (`scripts/fuzz.py:511-524`, `scripts/fuzz.py:554-569`, `scripts/fuzz.py:633-637`). |
| **CONFIRMED** | Admission wiring | `--admission` is passed to `CorpusManager`; REPRL+gain additionally creates a shared union, prefilters non-gaining worker results, and returns gains to the parent's single persistence point. Other backend/policy combinations reach parent-side `add_seed()` without this prefilter (`scripts/fuzz.py:155-165`, `scripts/fuzz.py:296-314`, `scripts/fuzz.py:432-445`, `scripts/fuzz.py:574-589`). |
| **LIKELY** | Shared-union/persistence atomicity | In REPRL+gain, a worker merges coverage into the union before the parent attempts `add_seed()`. If persistence declines or loses that seed, later rediscovery may no longer appear novel even though no corresponding corpus entry was retained (`scripts/fuzz.py:310-314`, `scripts/fuzz.py:438-445`, `scripts/fuzz.py:584-589`). |
| **CONFIRMED** | Reproducibility scope of `--seed` | The argument offsets per-iteration daemon seeds, but parent replay decisions use the unseeded module PRNG and worker mutation/crossover decisions mix in the OS PID. Thus `--seed` alone does not reproduce operation selection across campaigns (`scripts/fuzz.py:125-130`, `scripts/fuzz.py:327-330`, `scripts/fuzz.py:358-361`, `scripts/fuzz.py:501-509`). |
| **CONFIRMED** | Backend reporting after fallback | `coverage_mode` is computed as REPRL coverage before the shared-memory check changes `args.exec` to process mode, so the status line can report `coverage=reprl+shmem-edges` together with `exec=process` after fallback (`scripts/fuzz.py:419-430`, `scripts/fuzz.py:459-465`). |
| **CONFIRMED** | SIGTERM cleanup | The worker handler explicitly closes only a `ReprlRunner` and then uses `os._exit(0)`; normal worker exit also registers the same REPRL close routine with `atexit` (`scripts/fuzz.py:263-274`). The parent's fallback reaper matches command lines by binary-path substring rather than parent/child identity, so separate campaigns using the same binary path are not isolated from that cleanup (`scripts/fuzz.py:277-293`, `scripts/fuzz.py:417-418`). |
| **LIKELY** | Interrupted union snapshot ordering | After `KeyboardInterrupt`, the parent saves and closes/unlinks the shared union before cancelling and terminating workers, so workers may still be updating it during the final snapshot (`scripts/fuzz.py:609-613`, `scripts/fuzz.py:627-631`, `scripts/fuzz.py:640-648`). The general-exception path terminates workers and re-raises without the final union save/close block (`scripts/fuzz.py:614-625`, `scripts/fuzz.py:627-631`). |
| **SPECULATIVE** | Persisted ID collisions | Persistence is serialized in the parent, which removes cross-worker write concurrency, but this file neither constructs evaluated-seed IDs nor shows collision/atomic-write behavior inside `add_seed()` or `add_crash()`. Dry-run IDs are only iteration-derived, so collision resistance for evaluated corpus entries and findings cannot be established from this file (`scripts/fuzz.py:384-390`, `scripts/fuzz.py:574-589`). |

## 3. Effectiveness gaps

- **Static operation mix.** With a non-empty corpus, defaults assign 75% of submissions to fresh generation, 12.5% to mutation, and 12.5% to crossover; when no seed is available, replay choices fall back to generation. These ratios are fixed and do not respond to observed gain rates (`scripts/fuzz.py:143-154`, `scripts/fuzz.py:501-509`, `scripts/fuzz.py:358-378`).
- **Scheduler energy is only partially observable.** Every selected replay goes through `scheduler.select(seed_list_cache)`, so configured selection logic can affect which seed is chosen. This file does not pass execution, admission, runtime, or transformation outcome back to the scheduler, so dynamic energy updates are not wired here unless they derive entirely from metadata outside this loop (`scripts/fuzz.py:393-404`, `scripts/fuzz.py:501-509`, `scripts/fuzz.py:554-589`).
- **New seeds become selectable mid-run, with window latency.** Successful admission invalidates the cache before the next replacement task is submitted, allowing the next eligible replay decision to reload the corpus. Up to `batch_size` already-pending tasks keep their pre-admission operation and seed choices (`scripts/fuzz.py:544-552`, `scripts/fuzz.py:574-591`).
- **Coverage closes the corpus loop, not an adaptive scheduling loop.** In REPRL+gain, the shared union filters for gain, the parent persists the returned seed, cache invalidation exposes it to later selection, and periodic snapshots retain union state. Process-mode and hash admission delegate the admission decision to `CorpusManager`. No per-seed yield signal returns to scheduler logic in this file (`scripts/fuzz.py:296-314`, `scripts/fuzz.py:432-445`, `scripts/fuzz.py:501-509`, `scripts/fuzz.py:574-600`).
- **REPRL trades flag flexibility for throughput.** It reuses a persistent runtime and avoids shipping the large bitmap under gain admission, but ignores testcase-specific flags; process mode honors those flags at the cost of a fresh runtime process per testcase (`scripts/fuzz.py:167-175`, `scripts/fuzz.py:225-234`, `scripts/fuzz.py:248-260`, `scripts/fuzz.py:332-375`).
- **Primary throughput controls are static.** Worker count defaults to executor-managed CPU count, the in-flight window defaults to at least 32 or four times CPU count, and completion-driven replenishment prevents one slow task from imposing a batch barrier. Neither concurrency nor operation mix is adjusted from measured latency or gain (`scripts/fuzz.py:108-118`, `scripts/fuzz.py:457-465`, `scripts/fuzz.py:475-499`, `scripts/fuzz.py:544-552`).
- **The single daemon is a shared throughput and availability dependency.** All workers use the same localhost port with per-request 30-second timeouts, while health management observes only process exit and sleeps a fixed second on startup/restart (`scripts/fuzz.py:180-223`, `scripts/fuzz.py:447-455`, `scripts/fuzz.py:526-542`).
- **Evaluation telemetry is too coarse for effectiveness analysis.** The loop reports total successful executions, replay count, aggregate rate, finding classes, and worker errors, but it does not separate mutation from crossover, count generation fallbacks/no-ops, or report admissions and coverage gains by operation (`scripts/fuzz.py:467-473`, `scripts/fuzz.py:569-589`, `scripts/fuzz.py:593-608`).

## 4. Prioritized improvement list

1. Feed each seed selection's operation, runtime, and admission/gain result back into scheduler state so energy reflects measured campaign yield rather than selection-time metadata alone (`scripts/fuzz.py:501-509`, `scripts/fuzz.py:554-589`).
2. Make shared-union gain reservation and corpus persistence recoverable as one transaction or journaled sequence, preventing retained coverage from losing its selectable seed when persistence does not complete (`scripts/fuzz.py:310-314`, `scripts/fuzz.py:584-589`).
3. Add readiness probes, bounded request retries, and restart escalation for a live but unhealthy daemon; count successful evaluations rather than consumed task IDs when enforcing finite campaign length (`scripts/fuzz.py:447-455`, `scripts/fuzz.py:526-568`).
4. Record admission/gain yield separately for generation, mutation, crossover, and no-op fallback, then allow replay/crossover probabilities to adapt or be selected from evidence instead of remaining fixed defaults (`scripts/fuzz.py:143-154`, `scripts/fuzz.py:358-376`, `scripts/fuzz.py:593-608`).
5. Route a campaign PRNG derived from `--seed` through parent replay selection and worker operation choice without PID dependence, making reported effectiveness reproducible (`scripts/fuzz.py:125-130`, `scripts/fuzz.py:327-330`, `scripts/fuzz.py:501-509`).
6. Terminate and join workers before the final shared-union snapshot/close on interruption and apply the same resource-finalization path to general exceptions (`scripts/fuzz.py:609-631`, `scripts/fuzz.py:640-660`).
7. Define collision-resistant evaluated-seed/finding IDs and atomic create semantics at the parent persistence boundary, then expose collision/dedup counts in campaign statistics (`scripts/fuzz.py:574-589`, `scripts/fuzz.py:593-608`).
8. Validate metadata flag shape and recompute `coverage_mode` after backend fallback so execution configuration and campaign records remain accurate (`scripts/fuzz.py:350-357`, `scripts/fuzz.py:419-465`).
